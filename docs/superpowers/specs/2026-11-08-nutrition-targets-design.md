`target_id,revision,scope,date,calories_kcal,protein_g,carbohydrate_g,fat_g,weight_goal_kg,weight_goal_date,weight_change_kg_per_week,training_type,exercise_included,source,created_at,reason,status`

- Append-only revisions, independent from actual Health/Activities/Plan. `target_id=baseline-YYYY-MM-DD` for scope baseline (date=effective-from day), or `nutrition-YYYY-MM-DD` for scope daily (date=exact target day). revision integer>=1. Dates ISO yyyy-MM-dd in Perth, future dates allowed. created_at canonical UTC millisecond ISO. source nonempty<=120,reason<=2000. training_type free string<=120; exercise_included required boolean. status approved/draft/cancelled. Never app-upload targets.
- Calories required finite>0..20000. Optional protein/carbohydrate/fat grams finite0..5000. Optional weight_goal_kg>0..500,weight_goal_date ISO or empty,weight_change_kg_per_week signed-5..5 (storage validation, not recommended range). Blank numeric cells=null. Targets only after user approval.
- For each target_id/revision, identical repeated rows dedupe; differing payload same key is error. Across revisions ignore drafts; highest approved/cancelled revision determines that ID; cancelled removes it. An unapproved draft does not replace an earlier approved target.
- For a selected day, exact approved daily target wins; otherwise latest effective baseline date<=day. Baseline future changes do not rewrite earlier baseline days. Baseline macros apply only when that baseline is selected; blank daily macros mean unset (not inherited). Weight-management fields may fall back from daily blanks to selected baseline. No target means clearly unset, never inferred. Actual meals/weights remain untouched regardless of target changes/cancellation.
- Daily target whose created_at predates a later Plan revision on that date can display Coach review needed; never recalculate in app. Plan summary fallback supplies training label when target training_type empty. Do not add Garmin exercise calories even when exercise_included=false; that flag is explanatory, not an add-back instruction. Currently activity-energy estimates are not imported.
- Backend snapshot field nutrition_targets contains full validated ledger incl drafts/cancellations. Missing sheet on old deployment or malformed/conflicting target rows gives safe nutrition_error and omits nutrition_targets while training/notes still sync. Android keeps last valid target cache and shows stale/error state. Cache only updates on valid full ledger; old backend missing field does not erase it. Settings must show nutrition sync problems; Health uses simple user-facing stale/unavailable wording.
