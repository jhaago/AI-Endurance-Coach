# Health: individual meals, favourites and weight

User approved individual meal entries plus reusable favourites after the Health-tab proposal. Add a fifth native tab with manual calories (kcal) per portion, editable portions, dated editable meals/weights, optional global goal, favourite one-tap add and edit/remove. Trends: 30-day measured weight, seven-day measured average, 14-day logged calories. Missing days are gaps; totals are logged intake, not an assumption of complete food tracking. No calorie targets or weight-loss prescriptions.

## Fixed shared contract

New private sheet `Health`, append-only change ledger, exact headers:
`change_id,record_id,kind,date,name,calories_kcal,portions,weight_kg,note,deleted,updated_at`

- Immutable change_id (UUID), stable record_id (existing backend validId syntax).
- kinds meal/favourite/weight/goal. Meal/favourite names 1–120 chars. Calories finite 0–20000 per portion. Meal portions finite >0–100; favourite portions=1. Meal/weight dates valid ISO days. Favourite/goal date="".
- Weight/goal kg finite >0–500. Weight ID=`weight:<day>`; goal ID=`goal-weight`. Nonapplicable numeric fields null, weight/goal name=""; portions null. note string <=1000. deleted required boolean. updated_at valid UTC ISO at millisecond precision.
- Full-payload tombstones retain record content, fresh change_id and increasing per-record updated_at. Current record is greatest parsed timestamp then lexicographic change_id; retain deleted records in snapshot for merge safety. Favourite edits never alter prior logged meals.
- Request health array app <=30/server <=100. Validate whole mixed batch before writes. Same change_id/same canonical header payload retry is idempotent; differing payload is Health conflict. New changes appended via one bounded setValues call. Response ack_health explicit accepted change IDs and snapshot.health current records (including tombstones).
- Existing app clients stay compatible. New app must retain queued health changes if old bridge omits ack_health or snapshot.health. Blank date/name/note strings must be normalised back to empty strings when materialising Sheets records (generic records maps empty cells to null). Formula-safe string comparison must work with Sheets' literal text/leading apostrophe semantics and synthetic harness.
- SQLite existing schema is reused. Local current state + immutable outbox events saved atomically; snapshot+explicit health acknowledgements saved atomically. Persisted local current state merges with cloud by same timestamp/tie rule to retain offline edits/deletes.
